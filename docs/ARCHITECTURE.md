# Architecture

Updated every stage with a "what changed" list.

## Components

Built:

- `apps/rama` — Next.js 16 (App Router) app. The Site (Stage 2): `canvas/` renders a Blueprint as a building (pure functions: `layout`, `timeline`, `frame`, `draw`, `pick`), `components/site/SiteView` runs the replay deck and the brick finder, `components/inspector/` shows the Trust report, a Commit and a Brick in English with Confirm controls. Will hold Showroom, Discovery, Audit, Campus.
- `packages/blueprint` (Stage 1) — `extract(repoPath, opts) → Blueprint` from git and the file tree only; `metrics` (one function per figure, browser-safe); `diffBlueprints`; `draftGlossary` and `draftPurposes`; `site` (Stage 2: sites under `work/`, confirmations into a target's `.rama/`); the `rama` CLI (`extract`, `diff`, `site add|extract|check|draft|list`). The only writer of `blueprint/*.json` and `work/*/blueprint.json`. See its README.
- `packages/shared` — the types of MASTER-PROMPT §8 (`Blueprint`, `BrickNode`, `ImportEdge`, `Commit`, `Screen`, `FigureRef`, `Trail`, `Decision`, `Signoff`, `Finding`), one doc comment per field. `docs/BLUEPRINT.md` is generated from them.
- `packages/db` — Drizzle schema, the single migration `0000_init`, migrator and seed.
- `packages/trace` (Stage 3) — `capture()` photographs a target's real screens from its built app (Playwright, no secrets), finds every figure (traced by `data-rama-figure` or the `.rama/figures.json` overlay, untraced otherwise), re-executes traced figures with the target's own functions in a sandboxed Node process, and `buildTrail()` / `showroomOf()` turn a capture into the Showroom. CLI `rama-trace`. Convention: `docs/HOUSE-STYLE.md`.
- `packages/ceremony` (Stage 4) — decision cards and discovery sessions, named signatures (append-only in Postgres and mirrored to the target's `.rama/decisions.jsonl` and `.rama/signoffs.jsonl`), the supersede chain, the merge gate (`rama gate <repoPath> --base <commit>`), the walkthrough script, and imports of reconstructed records. CLI `rama-ceremony`.
- `packages/model` — `call()`, the one path to a model vendor: the seat's vendor and model (`resolveSeat`, refusing seats that break the rules), versioned prompt, the Anthropic and OpenAI adapters and one OpenAI-compatible adapter (Gemini, Grok, Kimi, Ollama, any compatible provider) over `fetch`, retries, one `model_calls` row per call recording the vendor and the seat. `runAgent()` (Stage 9) is the same door for a builder agent: Claude Code run in the product's folder with a versioned prompt, its own home and only the seat's key, retries that only ask for the answer, one row per run. `vendors.json` is the vendor registry (base URL, protocol, the seats each may hold, local or not, the builders that run on it); `seats.ts` holds the four seats and their rules (`seatProblems`: the builder's vendor never audits). `prices.ts` is the one dated price table (US$ per million tokens per model, the rupee rate, sources); `pnpm cost <stage>` turns a stage's `model_calls` into tokens and rupees.

- `packages/workbench` (Stage 7) — what makes House of Rama usable without a terminal: the GitHub client (`viewer`, `createRepository`, `pushTo` with the token in git's environment only), products (`newProduct`, `createProductRepository`), jobs (`startJob`, steps recorded in `work/.jobs/`), the site actions behind buttons (`refreshSite`, `photograph`, `runTests`, `callAudit` with the Test drive stand-in), the last test run (`runSiteTests`, `work/<site>/tests.json`), `siteStates` (metrics `stateOf` and `counts` over the capture, the test run and the sealed signatures), `linkHouseModules`, and `startTestDrive`. Keys and plain settings live in `packages/db` (`secrets.ts`, `settings.ts`); people in `members.ts`.

- `packages/workbench`, Stage 9 — the house stack and the build loop: `layDownScaffold` (templates/house-stack into an empty product, names put in, the gate keyed), `lintProduct` (House of Rama's own copy of the figures lint), `startBuild` / `build` (one lift at a time from the decided cards; after each, `checkLift`: the picture, the lint, the tests, the build and photographs with every figure worked out again, the merge gate from the house stack's lift, and the states), `pauseBuild`, the builders (`builders/`: `claude-code` wired through `runAgent`, `codex`, `gemini-cli` and `antigravity` stubs, `recorded` replaying a real build's lifts), and the seats (`seatsOf`, `chooseDefaultSeats`, `chooseProductSeats`, `productBuilder`). Test drive builds the sample from its cards (`sample.ts`) through the same loop.

- `packages/stage` (Stage 8) — the transparent isometric lakefront, pure functions over one Blueprint, safe in the browser: `resolveFeatures` (one building per thing the product does, from the product's `.rama/features.json` or drafted from its screens; files two buildings use stand in "Shared by several", code no screen uses in "Behind the screens"), `street(bp, features)` (the Street: buildings on a 2:1 grid with their floors and bricks, table plots lit when a building reads or writes them, roads for one building using another, the lake and the outside services as jetties), `building(feature, facades)` (the Building level: the real screenshots on the glass front with each figure's hotspot, the floors shows / decides / remembers / talks to through the side), `streetTimeline` / `laid` / `craneAt` (the replay), `streetAuditScript` / `buildingVerdicts` and the drone state (`stepAudit`, moved here from `apps/rama/canvas/audit.ts`), `drawStreet` / `drawBuilding` (Harmony tokens only, `palette.ts`), `pickStreet` / `pickBuilding`, and `understand` (the words open / inside / show me the code / go back). `read.ts` is the one reader of a product's file. The app's `components/lakefront/` and `packages/workbench` `siteLakefront` put it on screen.

- `packages/ears` (Stage 10) — the voice, a mouth and not a mind (Invariant 9). `voice.ts`: the Realtime session's configuration (prompt `voice.v1` as its instructions, push-to-talk, no reply of its own: `turn_detection` off, so the voice speaks only when asked) and the one event that makes it read a line (`sayEvent`). `grammar.ts`: `parseCommand` (yes, no, scrap everything, show me, open, show me the code, go back, what if, read the board, the six track questions), plain code. `track.ts`: `answerTrack`, each track question answered from a Trail only, untraced answered as untraced with the figure's name. `mouth.ts`: `mouthCheck`, the product facts in what the voice said that no builder line gave it. `conductor.ts`: `hear()`, the builder's side of the room: what a person said goes in as a turn with the speaker's name; the reply is builder lines (questions drafted by the drafter seat, narration by `narrate.v1`, track and what-if answers, read-backs) and places to show; a yes decides the card asked about, by the speaker. `rehearsal.ts`: acts 1 to 3 on the sample product. The browser side is `apps/rama/components/ears/`.
- `packages/board` (Stage 10, minimal) — `readBoard`: one webcam frame, read by `packages/model` (prompt `board.v1`, the drafter seat) into boxes, arrows and labels, kept under `work/<site>/board/` and shown as a draft map; nothing is decided from it.

Planned (folders hold only a README until their stage):

- `packages/audit` (Stage 5) — the second opinion: the fourteen checks of MASTER-PROMPT §7.3 as plain code (static ones over the TypeScript AST; the target's own `typecheck`, `build` and `test` scripts with PATH and HOME only; unsigned changes, unconfirmed phrases, open decisions), the auditor's reading through `packages/model` (prompt `audit.v1`, role auditor), the signed report in `audits` and `findings`, the replay script. CLI `rama-audit`.

## Data model

Every table carries `site_id`, `created_at`, `created_by` (Invariant 8); `site_id` is nullable only on `people`. `created_by` is a person id or `rama:<component>@<version>`.

| Table                 | Purpose                                                                                                                                                                                                                                       | Append-only                                  | Since   |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ------- |
| `sites`               | one per target repository; primary key is `site_id`; `member_id` is the owning person                                                                                                                                                         | no                                           | Stage 0 |
| `people`              | members and reviewers; `name` unique; `email` unused since sign-in became username and password (2026-10-24); `role` trainer or customer (members.json, Stage 7), member or manager (`AUTH_MODE=password`); `site_id` optional home site      | no                                           | Stage 0 |
| `model_calls`         | one row per model call: prompt, version, sha256, role (the seat: builder, auditor, drafter or voice), vendor, model, input, output, status, attempts, tokens, ms; a builder run's output carries its session and cost                         | yes (trigger refuses UPDATE/DELETE/TRUNCATE) | Stage 0 |
| `audit_log`           | every write to the append-only ceremony tables                                                                                                                                                                                                | yes (trigger)                                | Stage 0 |
| `discovery_sessions`  | a discovery session in the site office; `reconstructed` and `source` when rebuilt from a record                                                                                                                                               | yes (trigger)                                | Stage 4 |
| `discovery_turns`     | one turn of a session: speaker, text, `draft` for a question Rama drafted                                                                                                                                                                     | yes (trigger)                                | Stage 4 |
| `decisions`           | decision cards (§8 Decision); a change is a new card with `supersedes`; every insert audited by trigger                                                                                                                                       | yes (trigger)                                | Stage 4 |
| `signoffs`            | named signatures on a screen or brick at a commit (§8 Signoff); a reversal is a new row with `supersedes` (and `withdrawn`); `seal`, House of Rama's Ed25519 signature over the record; every insert audited by trigger                       | yes (trigger)                                | Stage 4 |
| `audits`              | one audit of a site at a commit: auditor vendor and model, its `model_calls` row (`call_id`), `inputs_hash`, the report (runs, counts, narration, alterations, time machine, sign-off verdicts); every insert audited by trigger              | yes (trigger)                                | Stage 5 |
| `findings`            | one verdict per finding of an audit (pass rows for clean bricks too): brick, check, verdict, the checks' own verdict, the auditor's note when it lowered one; every insert audited by trigger                                                 | yes (trigger)                                | Stage 5 |
| `audit_confirmations` | a named person's confirmation of an audit report's drafted text (narration, alterations, time machine, reasons for lowering a verdict), unconfirmed until one exists; every insert audited by trigger                                         | yes (trigger)                                | Stage 5 |
| `sessions`            | a signed-in browser: sha256 of the cookie's token, the person, expiry, `revoked_at` (sign-out)                                                                                                                                                | no (revoked by update)                       | Stage 6 |
| `secrets`             | a key entered in Settings (Anthropic, OpenAI, Gemini, Grok, Kimi, GitHub): AES-256-GCM ciphertext under `work/.secret-key`, the last four characters for the masked display, the last Test's light and sentence; replaced or removed in place | no (replaced in place)                       | Stage 7 |
| `settings`            | plain settings: the GitHub account or organisation products are created under; `brains` (the default seats) and `brains:<site>` (a product's own)                                                                                             | no (replaced in place)                       | Stage 7 |
| `pods`                | a pod on the floor by number                                                                                                                                                                                                                  | no                                           | Stage 6 |
| `bookings`            | a pod booked by a member: shift (`work` on a site, or `game`), start and end                                                                                                                                                                  | no                                           | Stage 6 |
| `checkins`            | a member's report of whether the product is in use (the campus's in use at 90 days)                                                                                                                                                           | yes (trigger)                                | Stage 6 |

## Critical path

Stage 0 and 1 (real function names):

- `pnpm dev` → `scripts/dev.mjs`: `docker compose up -d db` → `runMigrations(db)` and `seed(db, {memberName})` via `packages/db/src/cli.ts` → `next dev` (apps/rama) and `scripts/watch.mjs` side by side.
- Model calls: `call(req)` → `resolveSeat(seat, siteId)` (the site's seats from `storedSeats()`, else the default, else `resolveVendors(env)`; refuses with `seatProblems()` when the builder's vendor would audit, or a seat is unknown) → `loadPrompt(name, version)` → the seat's adapter (`anthropicComplete`, `openaiComplete` or `compatibleComplete(vendor, baseUrl)`) up to `MAX_ATTEMPTS` = 3 → `record(row)` into `model_calls` → output validated by the request's zod schema.
- Extraction: `rama extract` → `extract()` → `readCommitTree()` or `readWorktree()` + `worktreeBase()` → `parseSource()` per code file → `Resolver.resolve()` per import → `mergeGlossary()` → `readHistory()` → `assignLayer()` per brick → `findScreens()` → `canonicalJson()`. `pnpm extract:self` writes `blueprint/self.json`; `pnpm check:self` (`--check`) fails on drift.
- Watcher: `runChecks()` → eslint, prettier, `tsc --noEmit` per package, vitest changed projects then full suite, `drizzle()` (drizzle-kit check + regenerate-into-a-copy drift probe), `gen-blueprint-doc.mjs --check`, `pnpm check:self` → `.watch/status.json`.

Stage 2:

- `rama site add <src>` → `addSite()` (`git clone --no-hardlinks` into `work/<id>/repo`, `site.json`) → `writeSiteBlueprint()` → `extract(repoDir, {overlay: 'worktree'})` → `work/<id>/blueprint.json`; `registerSite()` inserts the `sites` row for the local member. `rama site draft <id>` → `draftGlossary()` + `draftPurposes()` → `call()` → unconfirmed entries in `.rama/glossary.json` and `.rama/purposes.json`, saved per batch → `writeSiteBlueprint()`.
- Stage 9, the build loop: console Start build → `POST /api/site/[siteId]/act` → `productBuilder()` (the builder seat; `RAMA_BUILDER_RECORDING` replays a recording) → `startBuild()` → `build()`: `briefOf()` (the decided cards in force) → `layDownScaffold()` + `commitAll('Start from the house stack')` when the product is not on the house stack yet → per lift `driver.lift()` (`claudeCode` → `runAgent()` with `prompts/build.v2.md`, one `model_calls` row) → `checkLift()`: `writeSiteBlueprint()`, `ensurePackages()`, `lintProduct()` (in its own process, beside) `runSiteTests()` and `photograph()` (build, capture with `readConvention()`, re-execution), `showroomOf()` for traced and agreeing figures, `runGate(base = the house stack's lift)`, `siteStates()` → a step with its sentence, or a grey flag with the problems and "The builder fixes this in the next lift" → the next lift asks for the fix; `pushIfOnGitHub()`; Pause build → `pauseBuild()` stops before the next lift; done when the builder says so and `complete()` holds. Test drive: `SAMPLE_CARDS` decided by "Test drive" → `testDriveBuilder()` (the seat's builder when it can run, else `recorded(fixtures/sample-build)`) → the same `build()`.
- Stage 9, the seats: Settings → Brains (`<BrainsForm>`: the auditor list leaves out the builder's company) → `POST /api/settings/brains` → `chooseDefaultSeats()` (`choiceProblems()`) → `putSetting('brains')`; discovery's "Which brains will build, check and speak?" → `POST /api/site/[siteId]/brains` → `chooseProductSeats()` → `putSetting('brains:<site>')` + `decide('The brains')`; every call → `resolveSeat()`; the audit → `callAudit()` (the auditor seat's key) → `runAudit({builder})` → the report's first line, `byLine()`.
- Stage 8, the Street: `/site/[siteId]` → `consoleProps()` (`siteStates()`) → `siteLakefront()` → `readFeatures()` + `resolveFeatures()` → `street()` (with the shots of a capture at the Blueprint's commit) → `buildingState()` per building over `stateOf()` → `<StreetView>` → each frame `drawStreet()` (palette from the page's Harmony tokens, `livePalette()`); Play → `streetTimeline()`, `laid()`, `craneAt()`, `liftChip()`; Fly the audit → `streetAuditScript()` → `startAudit()` / `stepAudit()` → `buildingVerdicts()`; click → `toPicture()` → `pickStreet()`; words → `understand()` → `placeHref()`. `?b=` → `building()` + `buildingTrails()` (`showroomOf()` → `plainTrail()`) → `<BuildingView>` → `drawBuilding()`, `pickBuilding()`; Name this building → `POST /api/site/[siteId]/features` → `nameFeature()` → `writeFeatures()` + `audit_log`. `?at=code` → `<SiteView>` (the Brick level).
- `/site/[siteId]` → `locateSite()` → `readSiteBlueprint()` → `<SiteView>` → each animation frame `draw(ctx, state)` → `frame(state)` → `siteModel(bp)` (`layout()` + `timeline()`, memoised per Blueprint) → paint. Click → `toScene()` → `pick()` → `<Inspector view=brick>` → `reviewerParagraph()`, `edgePhrase()`, `brickFigures()`.
- Confirm → `POST /api/site/[siteId]/confirm` → `handleConfirm()` → person id from `people` → `snapshotOverlay()` → `confirmEdge()` / `confirmPurpose()` (overlay write, `writeSiteBlueprint()`) → `audit_log` rows (on failure `restoreOverlay()`, 503) → `router.refresh()` re-reads the Blueprint.

Stage 3:

- `rama-trace capture <site>` → `readScreensConfig()` → `sh(install/build)` → `startApp()` (PATH and HOME only) → Playwright per screen: `goto` → steps → grow viewport → `collectFigures` (page-figures.js) → `screenshot` → `screenForRoute(bp, route)` for the bricks → `reexecute()` per traced figure → `runInSandbox()` (harness or `fn(...data-rama-args)`) → `work/<site>/capture.json` + `shots/`.
- `/site/[siteId]/showroom` → `readCapture()` + `readSiteBlueprint()` → `showroomOf()` → `buildTrail()` per traced figure → `<ShowroomView>` (hotspots from the captured boxes) → `<TrailPanel>` / `<UntracedPanel>`. Screenshots come from `GET /api/site/[siteId]/shots/[name]` → `shotResponse()`.
- `/site/[siteId]` passes the captured screens to the Brick view's "On screen" thumbnails.

Stage 4:

- `/site/[siteId]/walkthrough` → `readCapture()` + `readSiteBlueprint()` + `readSignoffs()` / `readDecisions()` (the target's `.rama/*.jsonl`) → `showroomOf(capture, bp, signaturesInForce())` → `walkthrough()` (one step per Blueprint screen, statement from traced figures and decided cards) → `<WalkthroughView>`; Read aloud → `speechSynthesis.speak()`; Confirm → `POST /api/site/[siteId]/sign` → `handleSign()` (captured commit must match, supersedes the signature in force) → `sign()`: a transaction holding the site's advisory lock runs `checkChain()` and inserts into `signoffs` (trigger `signoffs_audit` → `audit_log`; unique `signoffs_supersedes_once`); after the commit a second locked transaction runs `syncMirror()`, appending every committed row missing from `.rama/signoffs.jsonl` (a `MirrorError` if the file cannot be written, repaired by the next write) → `router.refresh()`.
- `/site/[siteId]` → `signaturesInForce(readSignoffs())` at the Blueprint commit → `signedScreens` → `frame()` → `brickMarks()` (red / amber / green dots); the Trust report → `signatureCoverage()`.
- `/site/[siteId]/discovery` → `listSessions()` + `listDecisions()` → `<DiscoveryView>`; `POST …/discovery/sessions|turns` → `startSession()` / `addTurn()`; `POST …/discovery/ask` → `draftQuestion()` → `call({name:'discovery', version:1, role:'builder'})` → a draft turn; `POST …/decisions` → `decide()` (row audited by trigger, mirrored to `.rama/decisions.jsonl`).
- `rama gate <repo> --base <commit> [--test-report <json>]` → (`packages/blueprint/src/cli.ts` loads `packages/ceremony/src/cli.ts`) → `runGate()`: `extract(repo)` at HEAD and at the base (screens and bricks of both count), `changesSince()` (`git log --first-parent -m --name-status -M base..HEAD`: merges with what they brought in, renames with both paths), `.rama/signoffs.jsonl` at HEAD and at base (must only grow; with `--public-key`, only lines whose seal verifies count, `verifySeal()`), `passingFromReport()` → `evaluateGate()` → `formatGate()`; exit 0 / 1 / 2 (usage).
